How Synapse0G optimizes an agent

Two layers that run for every agent, one optional learned ranker. Nothing ships unless its safety rule holds and the firewall finds nothing broken.
1 · Graph layer

Compile and rewrite the graph

runs at compile time, every job
1Trace each step once on a sample input: what it really reads and writes
▼
2Lift to SIR: steps + data edges + an effect per step
pure · read · write · external · irreversible
▼
3For each pass (parallelize, memoize, cse, dce, …): check its precondition against the effects
▼
4Holds → apply  ·  fails → refuse, with the reason
irreversible steps: never moved, cached or run
▼
5Audit the rewritten graph → optimized SIR → code (optimized_agent.py)
Supplier check: 4 lookups run in parallel, the policy step is cached, place_order is flagged.
2 · Call layer · heuristic search

Find per-step model changes

runs in a study, on tuning tasks only
1Baseline twice, unchanged: which tasks are stable, how much cost and time drift by chance
▼
2Profile each step: tokens, hidden reasoning, cost, repeats
▼
3Candidates, ranked by predicted saving: reasoning off · cheaper model · cache marks · trim old tool results · reuse · output cap. Under 3% predicted → skipped
▼
4Try the best one beside an unchanged control, same tasks, same moment
▼
5Firewall: no stable task breaks (rechecked) · pass count not lower · cost or time better with 95% confidence (paired bootstrap) · not >10% slower
▼
6APPROVE → keep it, re-profile  ·  BLOCK → refuse with reason  ·  repeat (≤ 6 trials)
▼
7Held-out tasks it never saw: final verdict and the reported numbers
Supplier check: kept reasoning off ×3 and a cheaper model ×2; refused the cheaper model on the quote step (36.7% slower). Held-out: 72% cheaper, 20/20 right.
3 · Learned ranker (optional)

Random forest pass policy

in the engine; not in the live demo path
111 graph features, measured before a pass: nodes, edges, model steps, reads, writes, protected steps, critical path, wall time, tokens, cost
▼
2One forest per pass (32 trees, depth 4) predicts two things: gain % and break risk
▼
3Score = gain ÷ (1 + risk) → ranks passes in the beam search; gain inside the noise band → not tried
▼
4Its pick still goes through the precondition and the firewall; no forest for a pass → falls back to the pass's own estimate
Trained on the train split only, checked on held-out tasks, and refuses to run if tasks leak between them.
